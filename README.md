# 家具选择确认表

用于按空间比较家具候选方案、确认选项并汇总报价的静态网页。

## GitHub Pages

上传本目录中的文件到 `vince-zh/furniture-selection` 仓库根目录。
在仓库 Settings > Pages 中选择 Deploy from a branch，分支 `main`，目录 `/ (root)`，然后保存。
部署完成后，通过 Pages 设置页显示的正式地址访问。

## 数据迁移

点击“导出为 Excel”保存完整项目，再在新网址点击“上传备份”恢复。
也支持上传以前导出的 JSON 备份。
日常修改保存在当前浏览器。点击“发布”才会把当前完整项目提交到 GitHub 并更新网站。
本地图片目录需要在新网址重新设置并授权。

## 手动发布

1. 在 GitHub 创建 fine-grained personal access token，资源所有者选择 `vince-zh`，仅授权 `furniture-selection` 仓库，`Contents` 权限选择 `Read and write`，设置较短有效期。
2. 在网页点击“发布”，输入凭证并确认公开当前清单、报价和图片。
3. 等待“发布完成，网站已更新”。提交成功与网页部署完成是两个独立状态。
4. 其他浏览器点击“载入发布项目”获取最新内容。先导出 Excel 保存未发布的修改，该操作会替换当前本地项目。

凭证仅用于本次 GitHub API 请求，不保存到浏览器、项目备份或仓库。不要在聊天、清单备注或公开代码中放凭证。
仓库发生新发布时，旧版本会被拦截；请先备份本地修改，载入最新项目，再手动合并后发布。
这不是实时协作，两个人不能把不同的完整快照自动合并。应先载入最新版，再修改并发布。
设计师需要自己的 GitHub 账号，并被邀请为此仓库协作者。GitHub 暂不支持仓库协作者使用 fine-grained token 写入他人的个人仓库；这种情况下，设计师可使用短期 classic token，仅勾选 `public_repo`（会授权其有权写入的公开仓库，不仅限于此仓库）。两个人不要共用凭证。

## 发布内容

`published-project.js` 包含已经确认公开的家具清单、报价和图片。新访客默认加载此项目；已有本地内容的浏览器不会被自动覆盖。
公开仓库保留历史版本，即使后续移除图片或清单，也不代表历史数据已从 GitHub 删除。

## Excel 导出

Excel 包含“候选清单”“总报价”“空间汇总”，保留未确定商品的位置、确认状态、费用和可点击的商品链接。
隐藏的“项目备份”工作表包含完整项目和图片，可通过“上传备份”恢复；不要删除或修改此工作表。
上传导出的 Excel 会恢复其中的完整备份，不会将手动修改过的可见清单单元格当成新的项目数据。
